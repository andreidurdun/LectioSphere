## 1. SECURITATE

### Cerințe Non-Funcționale:
- Autentificare și autorizare robustă: Utilizatorii trebuie să își poată accesa conturile în siguranță
- Protecție împotriva atacurilor comune: CSRF, XSS, SQL Injection
- Confidențialitatea datelor: Informațiile personale ale utilizatorilor trebuie protejate
- Control al accesului: Utilizatorii pot accesa doar propriile date și resursele permise

### Soluții Arhitecturale Implementate:

#### 1.1 Autentificare JWT (JSON Web Tokens)
Package: djangorestframework-simplejwt

- Token-based authentication pentru API-ul REST
- Refresh tokens pentru menținerea sesiunilor fără a cere re-autentificare frecventă
- Token blacklisting pentru invalidarea token-urilor la logout
- Tokens stocate pe client, reducând overhead-ul serverului

#### 1.2 Django AllAuth + Social Authentication
Packages: django-allauth, social-auth-core, social-auth-app-django

- OAuth2 pentru autentificare prin Google
- Gestionare centralizată a conturilor și profilurilor
- Email verification pentru validarea utilizatorilor noi
- Password reset securizat

#### 1.3 Django Security Middleware
- CORS Headers (django-cors-headers) pentru controlul accesului cross-origin
- CSRF Protection nativ în Django
- SQL Injection Protection prin Django ORM
- XSS Protection prin template escaping automat

#### 1.4 Permission Classes (REST Framework)
IsAuthenticated, AllowAny

- View-level permissions pentru controlul accesului la endpoint-uri
- Object-level permissions pentru resurse specifice utilizatorilor
- Verificări de proprietate în views (ex: user poate șterge doar propriile notificări)

## 2. PERFORMANȚĂ

### Cerințe Non-Funcționale:
- Timp de răspuns rapid: < 2 secunde pentru operații normale
- Încărcare eficientă a datelor: Minimizarea query-urilor către baza de date
- Scalabilitate: Suport pentru creșterea numărului de utilizatori

### Soluții Arhitecturale Implementate:

#### 2.1 Database Query Optimization
select_related(), prefetch_related()

- Eager loading pentru reducerea N+1 query problems
- Indexing pe chei străine și câmpuri des căutate
- Unique constraints la nivel de bază de date pentru performanță

Exemplu din cod:
shelf_books = ShelfBooks.objects.filter(shelf=shelf).select_related("book")

#### 2.2 Pagination și Filtering
- Pagination pentru liste mari de date (posts, events, books)
- Lazy loading prin REST API
- Query parameter filtering pentru căutări eficiente

#### 2.3 Django Extensions
Package: django-extensions

- Database optimizations și debugging tools
- Performance profiling capabilities

#### 2.4 Sentence Transformers Caching
Package: sentence-transformers
Model: all-MiniLM-L6-v2

- Model loading optimization (cached în memorie)
- Batch processing pentru embeddings
- Efficient similarity search folosind cosine similarity

#### 2.5 Background Processing
- Scraping asincron pentru evenimente și cărți
- Selenium WebDriver cu headless mode pentru scraping rapid
- WebDriver Manager pentru gestionarea automată a driverelor

## 3. DISPONIBILITATE ȘI FIABILITATE

### Cerințe Non-Funcționale:
- Uptime ridicat: 99%+ disponibilitate
- Gestionarea erorilor: Răspunsuri clare și utile pentru erori
- Data integrity: Consistența datelor în baza de date
- Fault tolerance: Reziliență la erori externe (API-uri terțe)

### Soluții Arhitecturale Implementate:

#### 3.1 Database Constraints
UniqueConstraint, ForeignKey constraints, NOT NULL

- Referential integrity prin foreign keys
- Unique constraints pentru prevenirea duplicatelor
- Validări la nivel de model (Django validators)

Exemplu:
class Event(models.Model):
    class Meta:
        constraints = [
            models.UniqueConstraint(
                fields=["source", "external_id"], 
                name="uniq_event_source_external"
            )
        ]

#### 3.2 Error Handling și Validation
- Serializer validation în REST Framework
- HTTP status codes corecte (400, 401, 403, 404, 500)
- Error messages descriptive pentru debugging
- Try-catch blocks pentru operații externe (API calls, scraping)

#### 3.3 Soft Delete Pattern
is_deleted = models.BooleanField(default=False)

- Păstrarea datelor în loc de delete hard
- Recovery capability pentru date șterse din greșeală
- Audit trail pentru modificări

#### 3.4 External API Resilience
- Timeout handling pentru requests HTTP
- Fallback mechanisms (ex: bestseller când nu există preferințe)
- Error propagation controlată către client

## 6. USABILITATE

### Cerințe Non-Funcționale:
- API intuitive: Endpoint-uri consistente și predictibile
- Error messages clare: Feedback util pentru utilizatori
- Response format consistent: JSON standard
- Mobile-friendly: Support pentru React Native client

### Soluții Arhitecturale Implementate:

#### 6.1 RESTful API Design
Standard HTTP methods: GET, POST, PUT, PATCH, DELETE

- Resource-based URLs: /books/, /posts/, /notifications/

#### 6.2 Serialization
Django REST Framework Serializers

- Consistent JSON format pentru toate răspunsurile
- Field-level validation cu mesaje clare
- Nested serialization pentru relații complexe
- Read-only fields pentru metadata (created_at, etc.)

#### 6.3 Google Books API Integration
External API: Google Books API

- Rich book data (covers, descriptions, ratings)
- Search capabilities (title, author, ISBN, publisher)
- Category browsing (fiction, bestsellers, etc.)
- Fallback data când cartea nu există local

#### 6.4 Recommendation System
ML: Sentence Transformers + Cosine Similarity

- Personalized recommendations bazate pe profilul utilizatorului
- Content-based filtering folosind descrieri de cărți
- User preference learning din cărțile citite
- Fallback la bestsellers pentru utilizatori noi
